# CLI integration state table

[한국어](01.%20Tables.ko.md)

## Scan cache

| State | Command | Expected result |
| --- | --- | --- |
| Missing index or malformed JSON | `status` | Scan current files and rebuild the index |
| Stable size and timestamp with exclusive read locks | `status`, `commit` | Succeed without opening working or stored content |
| Only the timestamp changes | `status` | Matching bytes leave the commit unchanged |
| Same key identifies different bytes locally or in another worktree | `status` or `commit` | Report an error and preserve both copies |
| Size or time changes, or the timestamp is ambiguous | `status`, `commit` | Detect the edit and capture the new bytes at commit |

## Worktree integration

Each row is a step in one temporary workspace. Exit code 0 means success, 1 an operation error, and 2 a conflict or rejected fast-forward.

| State | Command | Expected result |
| --- | --- | --- |
| Existing file differs from the source commit | `worktree add` | 1. File preserved, worktree not registered |
| Existing file matches the source commit | `worktree add` | 0. Worktree registered, ignored `.meta` not copied |
| Only B changes to x2, A still has x1 | `commit`, `merge B` | A receives x2 and retains x1. B with a zero budget prunes x1 |
| A and B change x2 to x3 and x4 respectively | `push`, `merge`, `merge --theirs` | First two return 2 with files and branches preserved. Choosing the incoming path applies x4 |
| A peer has an old copy | `restore` | Restores x1. A subsequent restore that would overwrite the working edit returns 1 |
| A, B and C commit separate paths | `sync A B C` | All three folders contain identical contents at all three paths |
| A deletes a file, C has an uncommitted edit | `push C` | 1. Edit preserved. Push propagates the deletion once C is clean |
| Budget reduced to zero | `gc`, `restore` | Current snapshot survives. Restore returns 1 after the last x1 copy disappears |
| External edit at a path in a pending journal | `recover`, `commit` | 1. Edit and journal survive. After restoring the expected value, two recoveries both return 0 |
| Path inside a registered worktree | `worktree add` | 1. Nested registration rejected |
