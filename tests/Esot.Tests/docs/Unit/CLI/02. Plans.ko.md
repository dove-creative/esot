# CLI 통합 테스트 계획

[English](02.%20Plans.md)

## 파일 검사 캐시

`Program.ScanChecks`는 임시 파일을 읽기 잠금해 캐시 적중 시 실제 읽기가 발생하는지를 검사한다. SHA-256 키 위치에 다른 바이트를 넣어 같은 길이의 마지막 블록 불일치와 다른 워크트리 사본의 크기 불일치를 재현한다. 시각만 변경, 크기만 변경, 불확실한 시각으로 연속 수정, 캐시가 없는 작업본, 손상된 캐시 JSON도 검증한다.

## 워크트리 연동

[상태표](01.%20Tables.ko.md)의 행은 [실행 코드](../../../Program.cs)의 `Program.Integration`이 순서대로 검증한다.

1. 임시 `ESOT_HOME`과 폴더 A·B를 준비하고, 원본과 불일치하는 기존 파일의 보존 및 일치하는 폴더의 등록을 확인한다.
2. 한글 파일명 `토끼.psd`에 구분 가능한 내용 x1~x4를 기록한다. 종료 코드, 충돌 경로, 전후 `status`, 파일 내용, 송신 로그, 저장 사본의 존재를 비교한다.
3. C를 추가해 복원과 세 워크트리 동기화를 검증하고, 외부 편집이 있는 C에 삭제 커밋을 푸시했을 때 파일이 보존되는지 확인한다.
4. 보관 한도를 0으로 낮춰 정리와 복원 실패를 검증하고, 대기 저널과 외부 편집을 만들어 복구 거부·재시도·반복 실행을 확인한다.

러너는 같은 프로세스에서 `Cli.Main`을 호출하고 표준 출력·오류와 반환값을 수집한다. 파일과 Git 저장소는 실제로 생성한다. 각 단계는 이전 단계의 워크트리 상태를 이어받는다.
